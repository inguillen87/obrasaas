# ObraSaaS — recuperación SaaS y QA/QC, 17/09/2026

## Decisión y alcance real
La rama master combina una interfaz de 14 módulos con autenticación simulada y un estado JSON compartido. No es una base segura para incorporar datos reales de clientes. Se recuperó la rama codex/platform-ux-foundation, commit d8a3612, en codex/saas-recovery-20260917. Ambas historias divergen: 108 commits exclusivos de master y 327 exclusivos de la base recuperada. No se debe fusionar ni reemplazar producción automáticamente.

La recuperación conserva Clerk, Organization/TenantMembership/ProjectMembership, scoping por obra, permisos del servidor, compras, inventario, mediciones, certificados y el transporte WhatsApp durable existentes. La presencia de esos componentes no certifica todos sus flujos funcionales ni equivalencia visual con las 14 páginas actuales.

## Entrega nueva: inspecciones persistentes
- Modelos InspectionRecord e InspectionRevision; relaciones compuestas empresa/obra, idempotencia de alta, control optimista de versión y auditoría atómica.
- Borrador → revisión → aprobación, observación o rechazo. Sólo Dirección/Administración emiten dictamen; una no conformidad impide aprobar.
- Cinco plantillas sin umbrales universales: seguridad, pre-hormigonado, electricidad, sanitaria y terminaciones. Cada control exige su criterio y documento/revisión antes de enviarse.
- Historial append-only con trigger PostgreSQL; estados finales protegidos. Las huellas SHA-256 se describen como integridad, no como firma digital certificada.
- Interfaz Dark Obsidian recuperada del master: listado paginado, editor, revisión, historial y exportación JSON. Ruta /dashboard/inspections y alias /inspecciones.
- APIs /api/inspections y /api/inspections/[id], autenticación Clerk en proxy y DAL, RBAC, cuerpo limitado, respuestas privadas sin caché y rechazo de origen cruzado.

## Mapa de persistencia para los 14 módulos
Reutilizar las entidades canónicas existentes, no crear un Tenant paralelo a Organization ni duplicar Worker, Project o Supplier.

| Módulo | Entidades existentes o implementación necesaria |
| --- | --- |
| Dashboard | Organization, Project, Worker, AttendanceEntry/Shift; indicadores derivados, no cifras fijas. |
| Certificación | ProjectCertificateBook/PeriodHead/Version/Line/Deduction/Decision; validar la UI actual contra este dominio. |
| Coordinación | DailyLog y evidencias de avance existentes; adaptar lienzo y actividad al scope de la obra. |
| Ejecutivo | Agregaciones de presupuesto, cronograma y certificados; no persistir un ROI o SPI ficticio. |
| Compliance | AuditLog, inspecciones y documentación; score calculado con evidencia, sin garantía normativa automática. |
| Licitaciones | Pendiente un dominio Tender/Bid/BidLine con procedencia y fecha de cada pliego, no seis licitaciones estáticas. |
| Presupuesto | BudgetVersion, BudgetLine, BudgetEntry; decimales y revisiones. |
| Marketplace | Supplier, PurchaseOrder/Line, GoodsReceipt/Line, SupplierInvoice e InventoryLedgerEntry. |
| Libro de obra | DailyLog existente; pendiente folio formal, rectificaciones, jurisdicción y evidencia de firma aplicable. |
| Inspecciones | InspectionRecord e InspectionRevision incorporados en esta entrega. |
| Planos | Pendiente Drawing/Revision/Annotation/PunchIssue; ficheros privados fuera de PostgreSQL. |
| Cronograma | Task, TaskDependency, ScheduleBaseline/Task/Dependency y forecast existentes. |
| BIM | Pendiente importación IFC real y BimModel/Element/TaskLink; el visor visual no prueba un parser IFC. |
| Portal inversor | Pendiente titular/unidad/contrato/cuota/imputación y alcance de acceso individual; no asumir que un rol de lectura da acceso a todos los inversores. |

## WhatsApp y próximos criterios de aceptación
La consulta de lectura a Meta con la credencial local respondió HTTP 200 y nombre Test Number. No se envió ningún mensaje real, no se modificó el webhook de Meta y no se certificó un número productivo. Varias variables de la configuración preview recuperada contienen un valor común de relleno: no deben tratarse como claves válidas ni propagarse a un entorno operativo.

El transporte recuperado ya implementa el webhook /api/webhooks/whatsapp y propuestas humanas para acciones sensibles. Falta validar app secret, conexión cifrada, número real, remitente autorizado, recepción firmada, respuesta entregada e idempotencia de extremo a extremo. El preview de recuperación deja los despachos de Meta y las llamadas IA deshabilitados hasta completar esa verificación. No se agregaron cron jobs al perfil de preview.

La siguiente integración debe preservar las 14 interfaces actuales y sustituir cada mock por su dominio probado. ARCA, cobros/eCheq, firmas certificadas, IFC y offline completo siguen siendo entregas pendientes, no funcionalidades certificadas por este sprint.
